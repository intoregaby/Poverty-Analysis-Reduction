# 10 - Architectural Weaknesses (current state, no changes proposed)

Severity scale: **Critical** = can make a published statement misleading about verification or truth with no gate; **High** = materially weakens a core guarantee; **Medium** = limits reliability, auditability or scale; **Low** = hygiene. Evidence cites code and, where available, the stored Kamonyi run. No weakness below is inferred from a function name alone.

## Summary register

| ID | Severity | Weakness | Affected module(s) | Evidence |
|---|---|---|---|---|

## The ten requested focus questions

| # | Question | Answer | Weakness |
|---|---|---|---|
| 1 | Can the AI generate unsupported numerical claims? | Yes. Detection is after-the-fact and non-blocking in Node paths; the Python reviewer's number check is context-wide not claim-specific. | W4, W12 |
| 2 | Are calculations independently validated? | Only partly: national constants, A9.23 SE if retrievable, arithmetic identities, planted-driver unit tests. No runtime second implementation. | W6 |
| 3 | Are official-source retrieval failures handled correctly? | Recorded honestly per claim (`not_externally_verified`) but the run and report continue, the cache fallback missed existing files, and headlines blur causes. | W2, W5, W11 |
| 4 | Are published figures matched on equivalent definitions? | Mechanism exists (period, denominator, unit, geography, concept) but depends on hand flags; grid and VUP never verify. | W7 |
| 5 | Is the complex survey design handled? | Poverty SE yes (validated only when NISR PDF is read); other indicators have uncorroborated Taylor SEs; decomposition inference is bootstrap-based but model-dependent. | W8 |
| 6 | Can AI corrections introduce new mistakes? | Yes, demonstrated on Kamonyi. | W3 |
| 7 | Can reports continue after critical verification failures? | Yes; there is no blocking condition. | W2 |
| 8 | Can multiple LLM providers create inconsistent outputs? | Yes; two models, different params, duplicated logic. | W9 |
| 9 | Can results be reproduced? | Numbers: yes given same data/code/seed (not re-run by this audit). Narrative and external evidence: no. | W10 |
| 10 | Can it support district investigations across Rwanda? | Technically 30 districts via `board.py`, but only as a local single-process tool with hand-parsed verification and EICV7-specific constants. | W13 |

## What was not tested

This audit read code and stored artifacts and ran existing tests (Node 41 passed; `test_verification` 27 passed). It did **not** re-run the engine on the EICV7 data, re-contact NISR or any LLM provider, or run the complete Python suite (`test_investigation.py`).
